## Rule
The Golden Window engine must NEVER reject a time slot because the overlap is too short.
Any genuine direct overlap (≥ 1 minute) is captured and scored progressively.
Duration contributes to confidence_score but is NOT a filter.

**Why:** The original v1 had a hard 60-minute gate. This made Nexus feel like a calendar
validator rather than an intelligent planner. Removing it ensures a recommendation is always
produced when data exists, even if it's a compromise.

## Match quality tiers
| Quality     | Condition               | Confidence cap |
|-------------|------------------------|----------------|
| perfect     | all members available  | up to 100      |
| strong      | ≥ 75% members          | up to 100      |
| partial     | < 75%, ≥ 2 members     | up to 100      |
| compromise  | no direct overlap      | max 35         |

Compromise windows are generated by median-centre algorithm when a day has 2+ members
with availability but zero direct overlap.

## Confidence formula
- Direct overlaps: `round(min(coverage * 70 + durFactor * 30, 100))`
  where durFactor = min(duration / 240, 1)
- Compromise: `round((count / total) * 35)`

## Persistence layer
Three columns added to `groups` table (migration: `supabase/golden_window_persistence.sql`):
- `golden_window_data JSONB` — full GoldenWindow object snapshot
- `golden_window_computed_at TIMESTAMPTZ`
- `golden_window_stale BOOLEAN DEFAULT false`

Service: `lib/golden-window-persistence.ts` — saveGoldenWindow / loadSavedGoldenWindow / markGoldenWindowStale

**How to apply:** Run `supabase/golden_window_persistence.sql` in the Supabase SQL editor.
Migration is idempotent (IF NOT EXISTS).

## Stale detection
`saveAvailability` calls `markGoldenWindowStale(groupId)` as fire-and-forget after a
confirmed successful save. Stale is never set if the save itself fails.
The UI shows a banner ("Availability changed — Recalculate?") and does NOT overwrite
the saved result automatically — user must confirm.

## group-detail.tsx data flow
On mount: 4 parallel loads — getGroup + listGroupMembers + getGroupAvailability + loadSavedGoldenWindow.
allAvailability stored in state for on-demand computation (NOT computed on mount).
Computation only runs when user taps "Find Golden Window" or "Recalculate".
DB-loaded window skips cinematic → instant reveal.
Freshly-computed window plays cinematic (3s) then saves to DB in background.

## UX principle (must preserve)
Nexus is an intelligent planner, not a calendar validator.
If no perfect overlap: "I couldn't find a perfect overlap — this is your best option."
Never: "No Golden Window."
checkGoldenWindowRequirements() provides exact missing-data explanation when genuinely
no computation is possible (< 2 members, or < 2 members with availability).
