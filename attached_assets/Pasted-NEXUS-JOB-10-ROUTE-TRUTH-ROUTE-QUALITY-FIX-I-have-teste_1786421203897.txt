==================================================
1. NEVER CALL A LINEAR ROUTE A LOOP
==================================================

This is the most important rule.

The route's label, route type, description, waypoints and metadata must all agree with the actual geometry.

If:

isLoop === true

then the geometry must actually represent a meaningful loop.

If the geometry is effectively:

A → B → A

or substantially retraces the same route, it MUST NOT be classified as a loop.

Do not solve this by simply changing the label.

Fix the underlying route-generation/scoring logic.

==================================================
2. DETECT ROUTE RETRACING
==================================================

Inspect the full OSRM geometry.

Build a route-quality/retrace metric.

A route should receive a poor loop score when it:

- travels out along one road/path
- turns around
- returns along the same road/path
- contains large sections of overlapping geometry
- contains a very narrow corridor between outbound and return legs

A route can start and finish at the same location without being a good loop.

Start/finish proximity alone is NOT enough to classify something as a loop.

==================================================
3. GENERATE BETTER CANDIDATE LOOPS
==================================================

The current route generation appears to be based around:

start → directional point → start

This is producing fake "loops" that are really out-and-back routes.

Change the candidate-generation strategy.

Generate multiple genuine candidate geometries.

Candidates should ideally:

- leave the start area
- travel in one direction
- take a different path back
- form a circuit
- minimise retracing
- use real OSM paths/roads
- remain appropriate for jogging
- finish near the starting location

Do not simply generate one route and call it a loop.

Generate several candidates and score them.

==================================================
4. ROUTE QUALITY SCORE
==================================================

Create a route-quality score based on real geometry.

Consider at least:

DISTANCE FIT
How close is the route to the requested distance?

LOOP QUALITY
How genuinely circular/circuit-like is it?

RETRACING
How much route geometry overlaps itself?

RUNNING SUITABILITY
Prefer:

- footways
- paths
- pedestrian areas
- parks
- cycleways where appropriate
- quieter residential roads

Avoid where possible:

- major roads
- unsuitable highways
- excessive road crossings
- repetitive out-and-back sections

VARIETY
Prefer routes that explore multiple streets/paths/areas.

==================================================
7. ROUTE TYPE MUST COME FROM GEOMETRY
==================================================

Do not manually decide that a route is a loop simply because the planner requested a loop.

Determine route type from the actual geometry.

Possible classification:

LOOP
Start and finish are close AND route has low retracing AND forms a meaningful circuit.

OUT_AND_BACK
Start and finish are close BUT route substantially retraces itself.

LINEAR
Route does not return close to the start.

The UI should display the correct classification.
